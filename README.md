# FabFederate-CNC

A local research project for predicting measured CNC milling-tool wear. It prepares NASA recordings, trains centralized/local baselines and Flower FedAvg/FedProx models, evaluates held-out cases, and explains saved-model predictions with SHAP.

The React website is in `frontend/`. The Python backend and scientific calculations are in `src/`. Packaging maps that directory to the import name `fabfederate`, preserving the saved models’ Python module names. Generated data and models are stored separately. This is the project's single README; the supplied PDFs remain untouched.

## Run the website

The Python environment, frontend dependencies, NASA data and trained studies already exist in this workspace. Open two terminals in the repository root:

```bash
# Terminal 1: Python API
make -f tools/Makefile api
```

```bash
# Terminal 2: React website
make -f tools/Makefile frontend
```

Open [FabFederate](http://127.0.0.1:5173). Select **NASA optimized study** (`nasa-optimized`) for the new model comparison, **NASA main study** for the original results, or **NUAA additional benchmark** for the separately trained derived dataset. The five pages use saved artifacts and actual model inference. The API runs on `127.0.0.1:8000`; Vite proxies `/api` locally. No cloud account is required.

For a production build preview, keep the API running and use:

```bash
npm --prefix frontend run build
npm --prefix frontend run preview
```

Open [the build preview](http://127.0.0.1:4173).

## Fresh installation

Tested with Python 3.12, Node.js 24 and npm 11 on macOS. From the repository root:

```bash
python3.12 -m venv .venv
make -f tools/Makefile install
make -f tools/Makefile frontend-install
make -f tools/Makefile download
make -f tools/Makefile audit
make -f tools/Makefile prepare
```

`requirements.txt` contains the exact Python dependency versions used by `make -f tools/Makefile install`. `frontend/package-lock.json` records JavaScript versions. The environment template documents an optional `FABFEDERATE_EXPERIMENTS_DIR` override; export it in the shell when using another trusted artifact directory.

A fresh clone excludes the large saved studies. Create the first trained artifact set with `make -f tools/Makefile study CONFIG=configs/smoke.yaml STUDY_OUTPUT=artifacts/experiments/my-smoke`, then open the website. The existing workspace already contains the complete reviewed study.

The repo already supports React, TypeScript, Tailwind CSS and shadcn conventions. Run shadcn commands **inside `frontend/`**, for example `npx shadcn@latest add button`. Reusable components belong in `frontend/src/components/ui/`; the `@/` alias resolves to `frontend/src/`. This keeps generated UI imports consistent and keeps frontend tooling out of the Python root. Styles are in `frontend/src/styles/globals.css`. Setup references: [shadcn with Vite](https://ui.shadcn.com/docs/installation/vite), [Tailwind with Vite](https://tailwindcss.com/docs/installation/using-vite), [Motion for React](https://motion.dev/docs/react).

## Data, training and workflow

1. `make -f tools/Makefile download` retrieves the NASA-linked archive and records checksums under `data/raw/`.
2. `make -f tools/Makefile audit` checks channels, identities, measured labels and exclusions under `data/interim/nasa/`.
3. `make -f tools/Makefile prepare` creates case-disjoint splits, windows, features and client manifests under `data/processed/nasa/`.
4. `make -f tools/Makefile study` runs the configured comparison and writes a new study under `artifacts/experiments/new-study/`.
5. Evaluation writes held-out predictions, MAE/RMSE, client/run errors, communication cost, robustness and plots inside that study.
6. SHAP explains the selected model using its saved preprocessing and a training-only reference.
7. The local API serves completed studies to the React website and computes validated predictions. The CLI and API use the same model implementation.

Training is CPU-first on one development computer. Flower runs three logical clients through an in-process transport. Models include mean/median baselines, Random Forest, centralized MLP, one local MLP per client, FedAvg and FedProx. Group splits happen before windowing. Imputation/scaling follow the declared training-only policy; checkpoints and FedProx `mu` are chosen on validation, then final test evaluation runs after selection freezes.

Override settings and output locations without editing code:

```bash
make -f tools/Makefile study CONFIG=configs/smoke.yaml STUDY_OUTPUT=artifacts/experiments/my-smoke
make -f tools/Makefile study CONFIG=configs/default.yaml STUDY_OUTPUT=artifacts/experiments/my-study
make -f tools/Makefile study CONFIG=configs/efficiency.yaml STUDY_OUTPUT=artifacts/experiments/my-efficiency
make -f tools/Makefile study CONFIG=configs/spectral.yaml STUDY_OUTPUT=artifacts/experiments/my-spectral
make -f tools/Makefile report STUDY=artifacts/experiments/my-study
```

Existing study directories are never silently overwritten. Each study keeps its complete output together: `manifest.json` records configuration/hashes; `prepared/` records scenario data; `runs/` contains every scenario/seed; `models/` identifies the website's default scenario/seed; `metrics.csv`, `predictions.csv` and `rounds.csv` contain measured outputs; `figures/`, `attributions.json` and `report.md` contain research evidence.

The original reviewed study is `nasa-final`; `nasa-optimized` adds validation-selected neural settings and tuned classical baselines. `uniwear-nuaa` is a separate derived-data benchmark. `nasa-smoke`, `nasa-efficiency`, `nasa-spectral` and `nasa-reproduction` are separate completed studies. `nasa-study` is retained historical output marked superseded and excluded from API discovery. Moving the folders preserves historical manifests and their original executed-source paths/hashes; those records are not rewritten to imply the models were trained by the reorganized source.

## Predict and explain a feature file

Use the ordered feature columns listed in the selected model manifest. Measured wear is not a predictor input. With the existing example:

```bash
make -f tools/Makefile predict
make -f tools/Makefile explain
```

These write `artifacts/inference/prediction.csv` and `explanation.json`. For another input/model:

```bash
make -f tools/Makefile predict INPUT=/path/to/features.csv MODEL=artifacts/experiments/nasa-final/models/fedavg
```

The website provides a matching header and accepts a CSV with 1–1,000 rows, up to 10 MiB, for one selected row at a time. It rejects extra/reordered columns and nonfinite values. Its sample picker shows the first 200 held-out rows. Predictions display units, source identity when available, measured wear when supplied, and optional signed SHAP contributions. Models are loaded only from trusted project-created folders; uploaded serialized models are not accepted.

## Explanations and measured feedback

Mean and median models are constant comparison baselines: they intentionally ignore sensor inputs and therefore have zero SHAP contributions. The app labels this explicitly. Learned models show measurable contributions, small values use scientific notation, and a plain-language summary states which feature raises or lowers the estimate relative to the training reference. The initial model is selected by saved validation error, excluding constant baselines. SHAP uses three bounded permutations with a training-only reference; its attributions describe model behavior rather than physical causes.

Input compatibility checks compare features against saved training minima/maxima. This check is not a calibrated prediction interval or a universal wear threshold. A measured-wear form records operator-entered values against the exact experiment/model/sample under `artifacts/experiments/feedback/measurements.jsonl`. Entries remain pending review and do not change trained models or evaluation labels. Qualified measurements and a separate curated split are required before future retraining.

## Additional training

```bash
.venv/bin/python -m fabfederate download --dataset uniwear
make -f tools/Makefile study CONFIG=configs/optimized.yaml STUDY_OUTPUT=artifacts/experiments/my-optimized-study
make -f tools/Makefile study CONFIG=configs/uniwear_nuaa.yaml STUDY_OUTPUT=artifacts/experiments/my-nuaa-study
```

The optimized NASA study preserves the existing case split, three seeds, five scenarios and 30-round FL comparisons. Neural hyperparameters were selected on validation only, with candidate evidence under `artifacts/tuning/nasa/selection.json`. Optional baseline optimization adds Extra Trees, histogram gradient boosting and Ridge, recording every candidate validation score and selected parameters. Reported test gains are exploratory because the established test split has been reused across research iterations; a new untouched evaluation is needed for confirmation.

[Uniwear NUAA source card](docs/dataset_cards/uniwear_nuaa.md) documents the new attributed source, derived wear labels and held-out experiments. Its results are kept separate from NASA. See [findings](docs/results/findings.md) for actual errors.

## Dataset scope and remaining work

[NASA source card](docs/dataset_cards/nasa_milling.md): 167 runs, 146 measured wear labels, 21 unlabeled runs excluded from supervised training, 16 cases, six channels, processed sampling at 250 Hz, VB in millimetres. Cases are not verified independent physical tools. Default prepared data contains 1,027 windows and 36 predictors; the separate FFT study has 54 predictors.

[PHM source card](docs/dataset_cards/phm2010_milling.md): the CSV adapter exists, but the archive has not been acquired and no PHM benchmark result is claimed. Its available labeled cutters need a separate defensible validation protocol.

[Campus protocol](docs/campus_protocol.md): actual recordings, approval, compatible sensors/units and measured wear are still required for campus shadow validation. The adapter accepts approved read-only files. No CNC control is implemented.

SHAP describes model influence, not physical causation. No calibrated prediction interval, universal replacement threshold, formal privacy guarantee, industrial deployment result or guaranteed federated improvement is claimed. The full remaining TODO list is in [the implementation report](docs/implementation.md).
